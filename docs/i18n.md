# Internationalisation (English + Bangla)

HisabBD is fully bilingual. English (`en`) is the default and lives at `/`. Bangla (`bn`) lives under `/bn`. Both are real, statically generated, indexable pages linked by hreflang alternates. There is no locale detection, cookie or redirect, and no i18n library.

## Locale plumbing

`src/i18n/locales.ts`:

| Export | Behaviour |
| --- | --- |
| `LOCALES` | `["en", "bn"]` |
| `type Locale` | `"en" \| "bn"` |
| `DEFAULT_LOCALE` | `"en"` |
| `localePath(locale, path)` | `("en", "/about") → "/about"`, `("bn", "/about") → "/bn/about"`, `("bn", "/") → "/bn"` |
| `pathnameLocale(pathname)` | `"/bn"` or `"/bn/…"` → `"bn"`, else `"en"` |
| `switchLocalePath(pathname)` | The same page in the other locale (`/bn/about` ↔ `/about`, `/bn` ↔ `/`) |
| `HREFLANG` | `{ en: "en-BD", bn: "bn-BD" }` |
| `OG_LOCALE` | `{ en: "en_BD", bn: "bn_BD" }` |
| `HTML_LANG` | `{ en: "en", bn: "bn" }` |

`src/i18n/locale-context.tsx`: `LocaleProvider` (set once in `LocaleShell`) and `useLocale()` for client components. Server components take `locale` as a prop instead.

### How a page gets its locale

There is no `src/app/layout.tsx`. Each locale has its **own root layout**, so the server HTML carries the right `<html lang>`:

- `src/app/(en)/layout.tsx` → `<RootDocument locale="en">` (`<html lang="en">`) + `<LocaleShell locale="en">`, metadata from `rootMetadata("en")`
- `src/app/bn/layout.tsx` → `<RootDocument locale="bn">` (`<html lang="bn">`) + `<LocaleShell locale="bn">`, metadata from `rootMetadata("bn")` (Bangla default title/description)

`RootDocument`, `rootMetadata` and `rootViewport` live in `src/components/layout/root-document.tsx` (font, global CSS, analytics). Moving between `/…` and `/bn/…` is a full page load because it crosses root layouts; the language toggle is a plain link anyway.

Unmatched URLs in either locale render `src/app/global-not-found.tsx` (enabled by `experimental.globalNotFound` in `next.config.ts`). It can't know the requested locale, so it is English with a Bangla line and a link to `/bn`.

## Where strings live

| Kind of text | Location | Shape |
| --- | --- | --- |
| Site chrome: nav, search, quick picks, card CTA, calculator page labels, copy/share/save messages, Reset, footer | `src/i18n/ui.ts` | `ui[locale]`, typed by `UiStrings` (both locales must satisfy it) |
| Calculator name, summary, SEO, FAQs | `src/calculators/<name>/meta.ts` | `name`/`nameBn`, `summary`/`summaryBn`, `seo`/`seoBn`, `faqs`/`faqsBn` |
| Category names and descriptions | `src/calculators/categories.ts` | `name`/`nameBn`, `description`/`descriptionBn` |
| Calculator widget labels, errors, results, share text | Top of `<name>-calculator.tsx` | `const STRINGS = { en: {…}, bn: {…} } as const` |
| Number-field error sentences | `src/components/calculator/number-messages.ts` | `numberErrorMessage(code, { label, min, max }, locale)` |
| Long explanatory content | `content.tsx` / `content.bn.tsx` | Separate Server Components |
| Homepage hero, benefits | `src/components/home/home-page.tsx` | Local `en`/`bn` objects |
| About, Privacy, Terms | `src/app/(en)/<page>/page.tsx` and `src/app/bn/<page>/page.tsx` | Separate files per locale |
| Site tagline/description | `src/config/site.ts` | `tagline`/`taglineBn`, `description`/`descriptionBn` |
| Month and weekday names | `src/lib/format.ts` | `MONTHS`/`MONTHS_BN`, `WEEKDAYS`/`WEEKDAYS_BN` |
| Grading scale names | `src/calculators/education/grading-scales.ts` | `name`/`nameBn`, `description`/`descriptionBn` |
| Salary deduction preset names | `src/calculators/salary/deduction-presets.ts` | `{ name, nameBn }` |

Functions are allowed as dictionary values for interpolation, e.g. `count: (n) => \`${n}টি ক্যালকুলেটর\``.

## Rules for writing strings

1. **Add both languages in the same change.** `UiStrings` and the `as const` widget dictionaries make a missing key a type error. `validateRegistry` fails tests on empty Bangla meta.
2. **Use Western digits in Bangla text for new content**: `৳2,500`, `20%`. Formatting helpers always output Western digits with South Asian grouping, and most pages follow this. Exceptions: scale and paper names (`৪.০০ স্কেল`, `৫.০০ স্কেল`, `১ম পত্র`); the Bangla Date Converter's main result, which is conventionally written in Bangla digits (`১২ কার্তিক ১৪৩৩`); and examples that show Bangla-digit *input*. Users may *type* Bangla digits; parsing handles that.
3. **Bangla has no plural suffix.** Use `countBn(n, unit)` or a template like `${n}টি …`. English uses `pluralize(n, "year")`.
4. **Lists:** `joinList(items, locale)` → `"a, b and c"` / `"a, b ও c"`.
5. **Dates:** `formatPlainDate(date, { locale, weekday })` → `"5 October 2026"` / `"5 অক্টোবর 2026"`.
6. **Error labels** passed to `numberErrorMessage` are lower-case noun phrases in the target language that read naturally in "Enter the ___." / "___ লিখুন।".
7. **Tone:** plain, friendly, short. English uses British spellings ("favourite", "instalment"). Bangla uses everyday words; common English loanwords (ক্যালকুলেটর, লোন, ডিসকাউন্ট, সেভ) are fine.
8. Keep worked-example numbers identical across `content.tsx`, `content.bn.tsx`, FAQs and tests.

## Links

Always build internal links with `localePath(locale, path)` or the helpers in `src/components/layout/nav-links.ts` (`primaryNav`, `categoryNav`, `legalNav`). Never hard-code `/bn`.

The language toggle (`components/layout/language-toggle.tsx`) is a plain `<Link>` to `switchLocalePath(usePathname())`. Its text names the **other** language (`ui.en.nav.switchLocale = "বাংলা"`, `ui.bn.nav.switchLocale = "English"`).

## Mixed-language markup

Where a string in the other language appears inline (for example the secondary calculator name under the H1), it carries a `lang` attribute (`lang="bn"` / `lang="en"`) so screen readers switch voice.

## Search across languages

`buildSearchIndex(list, locale)` shows names and summaries in the page language but also indexes the other language's name and all keywords. Keywords mix English, Bangla and romanised Bangla ("chhar"). Searching "বয়স" on the English site or "age" on the Bangla site both work.

## Fonts

Anek Bangla (variable, `wdth`) is loaded with `latin` and `bengali` subsets for headings (`font-display`). Body text uses the system stack, which includes `"Noto Sans Bengali"` as a fallback.
